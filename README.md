# Bike Rental Bot

Telegram-бот для управления прокатом велосипедов и сопутствующими ремонтными
расходами. Проект рассчитан на небольшой прокатный бизнес, где владелец
оформляет контракты, принимает оплату и контролирует задолженности через
Telegram.

## Что делает бот

Бот хранит клиентов, контракты аренды, виртуальные кошельки и ремонтные долги
в локальной SQLite-базе. Владелец работает через защищённую админ-панель, а
клиент видит свой баланс и получает автоматические уведомления.

## Основные функции

- оформление аренды на срок в днях с недельным тарифом;
- пропорциональный расчёт оплаты за неполный недельный период;
- сохранение завершённых контрактов и их продление;
- виртуальные кошельки клиентов;
- автоматические списания за аренду;
- приоритет списания просроченной аренды перед ремонтом;
- учёт ремонтных долгов и частичных платежей;
- уведомления клиенту и владельцу о платежах, нехватке средств и сроках;
- напоминание за день до следующего списания;
- история финансовых операций;
- защита от двойного списания уникальными ключами операций;
- ежедневные резервные копии базы с хранением последних 30 копий;
- админская FSM-навигация с отменой текущего сценария;
- AI-помощник только для пользователей из `ADMIN_IDS`.

## Для какого бизнеса

Решение подходит для проката велосипедов, электровелосипедов, самокатов и
другого транспорта с посуточными, недельными или гибкими контрактами. Также
его можно использовать для мастерской, если ремонт оплачивается клиентом
через тот же виртуальный кошелёк.

## Установка

Требуется Python 3.11 или новее.

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

Создайте локальный файл `.env` рядом с `main.py`:

```env
BOT_TOKEN=токен_от_BotFather
GROQ_API_KEY=ключ_Groq
GROQ_MODEL=openai/gpt-oss-20b
ADMIN_IDS=123456789,987654321
CLEAR_DB_PIN=7777
```

Секреты нельзя добавлять в Git или отправлять в сообщения. Файл `.env`,
SQLite-база и резервные копии уже исключены через `.gitignore`.

Запуск:

```powershell
python main.py
```

Для Linux подготовлен файл `bike-bot.service` и отдельная инструкция
`ORACLE_SETUP.txt` для запуска через systemd.

## Как работает планировщик

При запуске бот создаёт или обновляет схему `debts.db`, делает резервную копию
и запускает `APScheduler`.

Проверка платежей выполняется каждую минуту:

1. проверяются напоминания за день до списания;
2. при наступлении срока проверяется баланс клиента;
3. сначала списывается аренда, затем ремонтный долг;
4. после успешной оплаты создаётся следующий период;
5. при нехватке средств уведомляются клиент и владелец;
6. завершённый контракт получает статус `completed`, а не удаляется.

Резервная копия создаётся при запуске и далее каждые 24 часа. Хранятся
последние 30 файлов в каталоге `backups/`.

## Как используются AI-отчёты

AI-панель доступна только администраторам. Перед каждым запросом бот формирует
актуальную сводку из базы:

- клиенты и балансы;
- активные и завершённые контракты;
- даты и суммы ближайших списаний;
- просрочки;
- открытые ремонтные долги и остатки.

Эта сводка передаётся в Groq вместе с запросом владельца. Доступны анализ
долгов и оплат, рекомендации по прокату и свободные вопросы. AI должен
опираться на переданные данные и сообщать, если информации недостаточно; он
не выполняет финансовые операции самостоятельно.

## Безопасность

- админские действия ограничены списком `ADMIN_IDS`;
- токены хранятся только в `.env`;
- база и backups не публикуются;
- внутренние ошибки AI не показываются пользователям;
- одновременно должен работать только один экземпляр polling-бота.
- systemd-сервис ограничен через `NoNewPrivileges`, `ProtectHome`,
  `ProtectSystem` и закрытые права файлов;
- Telegram polling не требует открытых входящих портов;
- на сервере рекомендуется включить UFW с разрешённым только SSH;
- SQLite не шифруется на уровне файла, поэтому доступ к серверу и резервным
  копиям должен быть защищён правами ОС и SSH-ключами.
