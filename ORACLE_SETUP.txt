Oracle Cloud Free VM setup

1. Create an Ubuntu 24.04 Always Free VM in Oracle Cloud.
2. Connect over SSH and install Python:

   sudo apt update
   sudo apt install -y python3-venv git ufw gnupg2 curl
   sudo mkdir -p /opt/bike_bot
   sudo chown "$USER":"$USER" /opt/bike_bot

3. Configure the firewall before enabling the service. SSH must be allowed first:

   sudo ufw default deny incoming
   sudo ufw default allow outgoing
   sudo ufw allow OpenSSH
   sudo ufw enable
   sudo ufw status verbose

   The bot uses Telegram polling, so it does not need an inbound application
   port. Do not open ports 80 or 443 unless you add a separate web service.

4. Copy main.py, requirements.txt, bike-bot.service and your local debts.db
   to /opt/bike_bot. Do not upload .env to GitHub.
5. Create the environment file on the server:

   nano /opt/bike_bot/.env

   BOT_TOKEN=your_telegram_bot_token
   GROQ_API_KEY=your_groq_api_key
   ADMIN_IDS=your_telegram_id

   Protect the secrets and private data:

   chmod 600 /opt/bike_bot/.env
   chmod 700 /opt/bike_bot
   chmod 700 /opt/bike_bot/backups 2>/dev/null || true

   Для off-site резервных копий создайте отдельную passphrase (не коммитьте её):

   umask 077
   openssl rand -base64 32 > /opt/bike_bot/.backup_passphrase
   chmod 600 /opt/bike_bot/.backup_passphrase

   Планировщик шифрует последний дамп через `gpg` и отправляет его
   администраторам Telegram раз в сутки. Если passphrase отсутствует, отправка
   пропускается без изменения локальных бэкапов.

6. Install dependencies and register the service:

   cd /opt/bike_bot
   python3 -m venv .venv
   .venv/bin/pip install -r requirements.txt
   sudo cp bike-bot.service /etc/systemd/system/bike-bot.service
   sudo systemctl daemon-reload
   sudo systemctl enable --now bike-bot

7. Check the bot:

   sudo systemctl status bike-bot
   journalctl -u bike-bot -f

Only one copy of the bot may run at a time. Stop the local Windows copy
before starting the server copy, otherwise Telegram will report a conflict.

## Внешние ключи и существующая база

Новые установки получают `PRAGMA foreign_keys=ON` и связи `rents.client_id`
и `repair_debts.client_id` с `clients.tg_id`. SQLite не добавляет такие FK в
уже существующие таблицы через `ALTER TABLE`; для production `debts.db`
нужна ручная миграция через `CREATE TABLE new_...`, `INSERT ... SELECT`,
`DROP TABLE` и `ALTER TABLE ... RENAME TO ...` после проверки сиротских строк.

## Мониторинг рестартов

Сделайте скрипт исполняемым и добавьте cron раз в 10 минут:

    sudo install -m 750 monitor_restarts.sh /usr/local/sbin/bike-bot-restarts
    sudo crontab -e
    */10 * * * * /usr/local/sbin/bike-bot-restarts

Скрипт сравнивает `NRestarts` с предыдущим запуском и отправляет алерт
администраторам при скачке на 3 и более (порог меняется через `ALERT_THRESHOLD`).
